# Bottomline Content Lab — Pilot

יישום פיילוט בעברית לתכנון וכתיבת תוכן לעסק יחיד. המסמך `Bottomline_Codex_MVP_Prompt.md` הוא מקור האמת. אין פרסום לרשתות, חיבור לחשבונות חברתיים או הבטחה לתוצאות שיווקיות.

## התחלה מקומית

נדרש Node.js 22.13 ומעלה ו־npm. נבדק ב־Windows עם Node 24.16.0. אין צורך בחשבון חיצוני או במפתח כדי להריץ את ההדגמה.

Windows PowerShell, מתוך תיקיית הפרויקט:

```powershell
npm.cmd ci
Copy-Item .env.example .env
npm.cmd run db:migrate
npm.cmd run demo:seed
npm.cmd run dev
```

macOS / Linux:

```bash
npm ci
cp .env.example .env
npm run db:migrate
npm run demo:seed
npm run dev
```

פתחו <http://127.0.0.1:3000>. בחרו ״נסה עם עסק לדוגמה״ או ״הגדר את העסק שלי״. פרטי העסק לדוגמה בדיוניים. העסק הריק נשמר בנפרד; החלפת סביבת עבודה אינה מוחקת נתונים. ב־PowerShell אפשר להשתמש ב־`npm.cmd` ו־`npx.cmd` אם מדיניות המחשב חוסמת קובצי `.ps1`.

לבדיקת גרסת production מקומית:

```powershell
npm.cmd run build
npm.cmd start
```

אין להריץ `dev` ו־`start` על אותה יציאה במקביל. שרת ברירת המחדל מאזין ל־127.0.0.1 בלבד.

## מסלול העבודה

1. ״העסק שלי״: ארבעה שלבים עם שמירת התקדמות. הזינו עובדות, קהל, מטרה, קול, דוגמאות אהובות ולא אהובות וטענות אסורות. שדות שאינם ידועים יכולים להישאר ריקים; ליצירת תוכנית דרושים לפחות שם עסק וקהל.
2. ״תוכנית התוכן״: בחרו חודש ומטרה. נוצרים 8 או 10 רעיונות, עם כיוון, צורך, נימוק ופרטים לבדיקה. אפשר לערוך, להזיז תאריך, לאשר, להסיר רעיון ללא טיוטה, או לבקש חלופה אחת. רעיון שכבר נוסח שומר על הפורמט שלו כדי שהטיוטה וההיסטוריה יישארו עקביים.
3. אשרו רעיון ולחצו במפורש על יצירת טיוטה. פוסט, קרוסלה, סטורי וריל מקבלים מבנים שונים. ריל הוא תסריט בלבד.
4. ערכו ושמרו גרסה, בקשו שכתוב בעברית או דחו עם סיבה. המקור וכל הגרסאות נשמרים. שינויים מחזירים את הטיוטה לבדיקה. אישור וסימון ״מוכן לפרסום״ אינם מפרסמים דבר.
5. העתיקו כיתוב או הורידו טקסט עם המבנה המלא. דרגו את התוצאה ודווחו זמן עריכה. מסך המשוב מציג נתונים שנרשמו בפועל ומייצא JSON מלא בעברית.

כללי העדפה, דוגמאות, טקסטים שאושרו, תיקונים וסיבות דחייה נכללים בהקשר לבקשות AI הבאות. זהו שימוש בהקשר שמור, לא אימון מודל. כללי העדפה מוצגים עם מקור ואפשר להסירם; היסטוריית הביקורות נשמרת לצורכי הפיילוט.

## יצירה אמיתית באמצעות OpenAI

הגדירו בסביבה המקומית של השרת, או ב־`.env.local` שאינו נכלל ב־Git:

- `OPENAI_API_KEY`: מפתח שלכם עם הרשאה וחיוב תקינים. אין להדביק מפתח בצ׳אט, בקוד או במשתנה שמתחיל ב־`NEXT_PUBLIC_`.
- `OPENAI_MODEL=gpt-4.1-mini`: ברירת המחדל. הדגם מופיע ב[תיעוד הרשמי](https://developers.openai.com/api/docs/models/gpt-4.1-mini); זמינות בחשבון המסוים נבדקת בשרת לפני יצירה.
- `DAILY_GENERATION_LIMIT=30`: מכסת ניסיונות יצירה משותפת לשתי הסביבות, לכל יום לפי Asia/Jerusalem. ניסיון שנכשל עדיין נספר, להגבלת הוצאה.

אפשר גם לבקש מ־Codex להגדיר מפתח דרך חיבור OpenAI Platform המאובטח. אין צורך למסור לו את המפתח כטקסט. אחרי שינוי משתני סביבה הפעילו מחדש את השרת.

שלושת שירותי היצירה משתמשים ב־SDK הרשמי וב־Responses API עם [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), Zod, בקשות ללא שמירת Responses (`store:false`), מגבלת זמן ואימות נוסף של מספרי שקופיות/פריימים ומשך ריל. עובדות העסק והיסטוריית המשוב נשלחות ל־OpenAI לצורך היצירה; הזינו מידע אמיתי רק בהסכמת בעלת העסק. בדיקת מודל באמצעות Models API דורשת גם הרשאת קריאה מתאימה במפתח מוגבל.

ללא מפתח, יצירה משתמשת בתבניות דטרמיניסטיות מוגבלות ומסומנת **״דוגמת הדגמה — לא נוצרה באמצעות AI״**. תבניות אלה אינן מדד לאיכות ההתאמה האישית של מודל אמיתי.

התבניות משתמשות בשירותים, בתחום, בקהל ובצרכים שנשמרו בעסק הנוכחי; דוגמאות הליווי העסקי הקבועות משמשות רק לזריעה הבדיונית. לא מומצאות תשובות מקצועיות כאשר חסר מידע. לאחר שינוי פרטי העסק יש ליצור תוכנית חדשה. הלוח מציג כברירת מחדל את התוכנית האחרונה לחודש; תוכניות קודמות נשמרות ואפשר לבחור אותן ב״תוכנית להצגה״.

אימות עם מפתח: שנו ושמרו שני פרטי עסק, צרו תוכנית לחודש חדש, אשרו רעיון, צרו טיוטה, בקשו ״קצר יותר, בלי סימני קריאה״, אשרו/דחו וצרו טיוטה נוספת. בדקו שהפרטים העדכניים והכללים נשמרו, שאין סיפור/מחיר/תוצאה שלא סיפקתם, ושהמקור מסומן AI. **המסלול החי לא אומת בסביבת הבנייה משום שלא היה מפתח.**

## משתני סביבה ומסד נתונים

| משתנה | שימוש |
| --- | --- |
| `DATABASE_URL` | ברירת מחדל `file:./data/pilot.db`; לאירוח `libsql://…` |
| `DATABASE_AUTH_TOKEN` | אסימון למסד libSQL מרוחק בלבד |
| `OPENAI_API_KEY` | אופציונלי ליצירה אמיתית, בשרת בלבד |
| `OPENAI_MODEL` | ברירת מחדל `gpt-4.1-mini` |
| `DAILY_GENERATION_LIMIT` | ברירת מחדל 30, מספר שלם חיובי |
| `PILOT_ACCESS_CODE` | קוד גישה משותף לפיילוט המאוחסן |
| `PILOT_COOKIE_SECRET` | סוד חתימה נפרד של לפחות 32 תווים |
| `APP_ORIGIN` | כתובת HTTPS מדויקת של סביבת האירוח, ללא לוכסן בסוף |

Next קורא קובצי env אוטומטית; פקודות המסד קוראות `.env.local` ואחריו `.env`. מסדי נתונים וקובצי סודות מוחרגים מ־Git.

המודל קטן במכוון: שתי רשומות workspace (עסק לדוגמה / העסק האמיתי), כל אחת עם פרופיל, תוכניות, רעיונות, טיוטות וגרסאות, אירועי ביקורת, העדפות, הזדמנויות ומשוב כ־JSON. Drizzle שומר אותן באותו מסד libSQL/SQLite עם מספר revision למניעת דריסת עדכונים בין חלונות. טבלת usage מונה ניסיונות באופן אטומי. `db:migrate` מבצעת את סכמת V1 האידמפוטנטית; אין מסד מקביל. זו בחירה לפיילוט קטן, לא לתשתית מרובת משתמשים. חותמות זמן נשמרות UTC ומוצגות בירושלים.

## בדיקות

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npx.cmd playwright install chromium
npm.cmd run test:e2e
npm.cmd run test:access
```

`test:e2e` בונה production, מפעילה שרת ביציאה 3100 ומסד בדיקות נפרד `data/e2e.db`, ללא מפתח. היא מאפסת רק את רשומות מסד הבדיקות. נבדקים 1440×1000 ו־390×844, התמדה, עריכה, היסטוריה, אישור/דחייה, העתקה, הורדות, משוב, הגדרה ריקה ויצירת הדגמה. `test:access` דורשת build קיים, מפעילה שרת זמני ביציאה 3201 עם נתוני בדיקה בלבד, ובודקת הגנת דפים/API, cookie חתום, מקור בקשה, אימות קלט, התנגשות כתיבות והתמדה אחרי אתחול תהליך. בדיקת ה־cookie נעשית בלקוח HTTP; HTTPS של אירוח ממשי לא נבדק.

בדיקות אינן משתמשות ב־`data/pilot.db`. צילומי Playwright נוצרים ב־`output/qa` ומוחרגים מ־Git. ראו גם `VERIFICATION.md`.

## איפוס, גיבוי וניקוי

```powershell
npm.cmd run demo:reset
```

הפקודה מאפסת רק את העסק הבדיוני; העסק שלכם נשמר. לפני ניקוי עסק אמיתי, ייצאו JSON ממסך המשוב ושמרו גיבוי מאובטח. לניקוי מקומי מלא, עצרו את כל שרתי האפליקציה, גבו ואז מחקו את הקבצים `data/pilot.db`, `data/pilot.db-wal`, `data/pilot.db-shm` אם קיימים, ואת בחירת הסביבה ב־localStorage בדפדפן. הריצו שוב migrate ו־seed. אל תשתמשו בתהליך זה על מסד משותף בלי גיבוי. ניקוי libSQL מרוחק נעשה אצל ספק המסד, עם בדיקת היעד וגיבוי מראש.

## שיתוף מאובטח עם לקוחה

לא בוצע deployment. כדי לארח:

1. צרו מסד libSQL/Turso פרטי וקבלו URL ואסימון. השתמשו בנתוני דוגמה עד לקבלת הסכמה להזנת מידע אמיתי.
2. העלו את המקור למארח Node תואם Next.js, למשל Vercel. הגדירו build כ־`npm run build`; במארח Node רגיל התחילו עם `node node_modules/next/dist/bin/next start --hostname 0.0.0.0 --port 3000` מאחורי HTTPS.
3. הגדירו בסודות המארח את `DATABASE_URL`, `DATABASE_AUTH_TOKEN`, `PILOT_ACCESS_CODE`, `PILOT_COOKIE_SECRET`, `APP_ORIGIN`, ואת מגבלת היצירה. אפשר ליצור סוד חתימה מקומי עם `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` ולשמור אותו רק במנהל הסודות.
4. לא להשתמש ב־SQLite מקומי במערכת קבצים זמנית של אירוח. הסכמה מאותחלת אידמפוטנטית בבקשה הראשונה, והדמו נוצר רק בכניסה לסביבת הדוגמה. אפשר להריץ מראש `db:migrate`/`demo:seed` מסביבה מהימנה המוגדרת לאותו מסד.
5. ודאו שביקור בלי cookie מפנה למסך קוד ו־API מחזיר 401; התחברו בקוד, ערכו פרט, בצעו deployment מחדש ובדקו התמדה. הגדירו את `APP_ORIGIN` לכתובת הנוכחית בכל preview. בלי קוד וסוד תקינים Vercel/סביבה עם APP_ORIGIN נשארת חסומה.
6. רק לאחר בדיקת AI אמיתית שתוארה למעלה, העבירו ללקוחה את הכתובת והקוד בערוץ פרטי. החלפת סוד החתימה מבטלת sessions קיימים.

הגישה היא קוד משותף זמני עם cookie חתום, HttpOnly, SameSite=Lax ו־Secure ב־production; היא אינה חשבון משתמש או מערכת הרשאות. הגבלת ניסיונות כניסה היא בסיסית ולפי תהליך שרת; אפשר להוסיף הגנת המארח בעת שיתוף ציבורי. כל מי שמחזיק בקוד יכול לקרוא ולערוך את אותו פיילוט.

## מבנה והיקף

- `src/app`: דפי Next, כניסה, API ו־CSS RTL.
- `src/components`: מסגרת האפליקציה, פרופיל, תוכנית, סטודיו ומשוב.
- `src/lib`: חוזי Zod, סכמת Drizzle והתמדה, דמו בדיוני, פעולות, הקשר AI וגישה.
- `scripts`: הכנת מסד ובדיקת גישה/אתחול.
- `tests`: יחידות ו־Playwright.
- `PILOT_SCRIPT_HE.md`: מסלול פגישה בן 10–15 דקות.

המגבלות לפיילוט: AI חי ואיכות עברית של מודל לא אומתו ללא מפתח; אין העלאת תמונות, הפקת תמונות/וידאו, נתוני ביצועים או שילוח לרשתות. נשמר קישור אופציונלי לתמונת מותג כמידע בלבד; התצוגה היא כרטיס טקסט בצבע המותג. אין ניטור חדשות, אימון מודל, fine-tuning או מדידת חיסכון מוכחת. כל תוכן, ובמיוחד טענות מקצועיות, דורש בדיקה אנושית. לא אומתו עדיין macOS/Linux או מסד/אירוח מרוחקים.
